# AI-Security-Guardian 商业化里程碑

## 1. 里程碑总览

| 里程碑 | 建议周期 | 阶段目标 | 核心产出 |
|---|---:|---|---|
| M1 私有化 Beta | 2-4 周 | 单企业可部署、可验收、可回滚 | 私有化部署包、迁移框架、发布准入、运维手册 |
| M2 私有化 GA | 4-6 周 | 单企业稳定交付 | 试点运行、审计/备份/恢复演练、响应闭环受控开放 |
| M3 多租户 Alpha | 6-8 周 | 建立租户隔离架构 | 租户模型、强制隔离、租户级 RBAC、越权测试 |
| M4 SaaS Beta | 8-12 周 | 建立商业闭环 | 自助开通、套餐配额、用量计量、SLO 监控 |
| M5 合规运营版 | 12 周+ | 支撑规模化销售和交付 | 合规证据、数据生命周期、灾备演练、客户成功看板 |

## 2. M1：私有化 Beta

### 目标

把当前系统从“工程基础可用”推进到“单企业私有化可部署、可验收、可回滚”。

### 范围

- 引入 Alembic/Flask-Migrate。
- 固化 PostgreSQL、Redis、模型目录、Nginx TLS、Docker Compose 部署。
- 将私有化 Beta readiness、E2E 验收、压测脚本纳入发布流程；真实封禁 readiness 作为更高风险门禁单独执行。
- 补齐发布包、安装文档、初始化脚本、回滚说明。

### 交付物

- 私有化部署包。
- 数据库迁移脚本。
- 上线检查清单。
- 运维手册。
- 回滚手册。

### 验收口径

- 新环境可从 0 部署成功。
- `check_production_readiness.py` 默认 `private-beta` gate 无 FAIL，允许 `DRY_RUN=true`。
- 若开启真实封禁，`check_production_readiness.py --gate real-enforcement` 无 FAIL，且 `DRY_RUN=false` 与审批/审计/回滚/解封/复盘证据齐备。
- `/readyz`、`/metrics`、核心 API 正常。
- 数据库迁移可重复执行。

## 3. M2：私有化 GA

### 目标

形成可以给首批客户交付的单企业版本。

### 范围

- 完成通知、响应、审计、报表的交付闭环。
- 响应动作加入审批、白名单、误封恢复演练。
- 建立备份恢复演练和证据留存。
- 建立试点运行指标。

### 交付物

- 私有化 GA 版本。
- 试点验收报告。
- 备份恢复演练报告。
- 响应误封恢复演练报告。
- 客户交付模板。

### 验收口径

- 单企业环境连续稳定运行 30 天。
- Web 重启后历史告警不丢失。
- 审计哈希链可校验。
- 响应动作可审批、可回滚、可审计。

## 4. M3：多租户 Alpha

### 目标

建立多企业商业化所需的租户隔离架构。

### 范围

- 增加 Tenant、Organization、User、Membership、Role、APIKey。
- 核心业务表增加 `tenant_id`。
- API、数据库、审计、报表、导出、Redis Stream 全链路带租户上下文。
- 增加租户越权测试。

### 交付物

- 多租户数据模型。
- 租户上下文中间件。
- 租户级 RBAC。
- 租户隔离测试集。
- 租户级配置管理。

### 验收口径

- A/B 租户数据互不可见。
- 任意跨租户访问被拒绝。
- 审计和报表均按租户隔离。
- Redis Stream 消息可按租户消费和追踪。

## 5. M4：SaaS Beta

### 目标

完成 SaaS 付费转化所需的商业闭环。

### 范围

- 自助开通企业空间。
- 套餐、订阅、配额、用量计量。
- 支持套餐升级/降级。
- SSO/MFA、通知中心、工单和状态页。
- 多实例运行、灰度发布、SLO 监控。

### 交付物

- SaaS Beta 环境。
- Plan/Subscription/Quota/UsageMeter 数据模型。
- 用量看板。
- 套餐限制策略。
- SaaS 运维后台。

### 验收口径

- 多客户可同时使用。
- 用量可计量、可限制、可导出。
- 套餐变更可立即影响权限和配额。
- 关键 SLO 可观测。

## 6. M5：合规运营版

### 目标

支撑中大型客户采购、合规审查和规模化运营。

### 范围

- 数据保留、归档、删除、导出。
- 合规证据包。
- 密钥轮换。
- 灾备演练。
- 模型质量运营和客户成功看板。

### 交付物

- 合规证据中心。
- 数据生命周期策略。
- 灾备演练报告。
- 模型质量看板。
- 客户成功运营看板。

### 验收口径

- 合规证据可按客户、时间范围、事件类型导出。
- 数据删除和导出流程可验证。
- 季度恢复演练通过。
- 模型误报率、漂移、版本回滚可运营。

## 7. 推荐排期原则

- 先完成 Phase A，再启动大规模多租户改造。
- `tenant_id` 属于架构级变化，应尽早进入主干。
- SaaS 计费不要早于租户隔离。
- 合规证据从 Phase A 就开始沉淀，Phase D 再体系化。
