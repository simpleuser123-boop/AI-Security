# AI-Security-Guardian 商业化落地路线图

## 1. 当前商业化判断

`ai-security-guardian` 当前已不是纯 Demo。项目已经具备 Flask 控制台、REST API、Socket.IO、JWT、基础 RBAC、Redis Stream、PostgreSQL 生产约束、审计哈希链、模型 manifest/registry、SMTP/Webhook 通知、响应调度、Prometheus 风格 `/metrics`、Docker/Gunicorn/Nginx/TLS 部署手册等生产化基础。

但距离商业化生产仍缺四类关键能力：

- 生产发布治理：正式数据库迁移、升级回滚流水线、版本管理、发布准入。
- 多租户隔离：租户模型、`tenant_id`、租户级 RBAC、租户级数据和配置隔离。
- SaaS 商业闭环：套餐、License、计量、计费、配额、客户自助开通。
- 规模化合规运营：数据生命周期、审计证据包、合规控制项、SLA/SLO、灾备演练。

## 2. Phase A：单企业私有化可用

### 技术目标

- 固化单企业部署形态：Web/API、Guardian、Redis、PostgreSQL、模型目录、Nginx TLS。
- 引入正式数据库迁移框架，替代仅适合首次空库的 `create_all()`。
- 将生产准入脚本、E2E 验收、压测、健康检查纳入 CI/CD。
- 完成模型、审计、响应、备份恢复的上线基线。

### 产品能力

- 单企业控制台可用：告警、规则、IOC、设置、报表、审计查询。
- 基础 RBAC 可交付：`viewer`、`analyst`、`admin`。
- 通知能力可配置：SMTP、Webhook、企业通知占位。
- 响应动作可控：dry-run、封禁、解封、定时解封、操作留痕。

### 安全合规

- 生产环境禁止默认密钥、默认管理员密码、明文管理员密码。
- JWT、CORS 白名单、SSRF 防护、命令注入防护、Redis 密码必须通过。
- 审计日志哈希链开启，关键操作写入 `audit_events`。
- 备份、恢复、误封恢复演练形成交付证据。

### 运维监控

- `/healthz`、`/readyz`、`/api/health`、`/metrics` 完整可用。
- 监控 Redis Stream 长度、pending、lag、模型就绪、检测延迟、审计巡检状态。
- 支持发布前 readiness 检查：私有化 Beta gate 允许 `DRY_RUN=true`，真实封禁 gate 单独要求 `DRY_RUN=false` 和审批/审计/回滚/解封/复盘证据。

### 验收标准

- 单企业环境稳定运行 30 天，无告警数据丢失。
- Web 重启后历史告警、规则、IOC、设置仍可查询。
- Web API P95 < 300ms；检测链路 P95 < 100ms。
- `pytest`、`verify_v1.py`、`benchmark_http.py`、`check_production_readiness.py` 全部通过；若开启真实封禁，额外要求 `check_production_readiness.py --gate real-enforcement` 通过。

### 预计工程任务

- 引入 Alembic/Flask-Migrate。
- 建立私有化部署包和离线安装说明。
- 固化 CI/CD 发布准入。
- 响应审批、白名单、误封恢复流程产品化。
- 完善通知失败重试可视化。

## 3. Phase B：多企业/多租户

### 技术目标

- 引入租户数据模型：Tenant、Organization、User、Membership、Role、APIKey。
- 所有核心业务表增加 `tenant_id`。
- API、DB 查询、审计、报表、导出、Redis Stream 消费全链路带租户上下文。
- 支持租户级规则、IOC、通知、模型策略、响应策略。

### 产品能力

- 企业空间管理。
- 成员邀请、角色分配、租户级 API Token。
- 租户级规则、IOC、报表、审计、响应配置。
- 租户间独立运营与权限边界。

### 安全合规

- 强制租户隔离，禁止跨租户读写。
- 增加越权测试和租户隔离回归测试。
- 租户级审计查询和证据导出。
- 租户级密钥、Webhook、SMTP 配置隔离。

### 运维监控

- 租户维度指标：告警量、响应动作、API 调用、队列积压、错误率。
- 租户级配额和资源占用监控。
- 租户级健康诊断。

### 验收标准

- A/B 两个租户的数据、规则、IOC、审计、报表互不可见。
- 任意 API 未带租户上下文时拒绝访问。
- 所有查询默认强制 `tenant_id` 过滤。
- 越权测试覆盖核心业务接口。

### 预计工程任务

- 数据模型增加租户体系。
- Repository 层封装强制租户过滤。
- Redis Stream message 增加 `tenant_id`。
- 前端增加租户切换和企业空间管理。
- 增加租户隔离测试集。

## 4. Phase C：SaaS 商业化

### 技术目标

- 控制面与数据面解耦。
- 支持租户自助开通、套餐、配额、计量、账单。
- 建立灰度发布、版本回滚、SaaS 运维控制台。
- 支持水平扩展和多实例部署。

### 产品能力

- 自助注册、企业开通、套餐升级/降级。
- 用量看板：告警量、资产量、检测量、通知量、响应动作量。
- 套餐限制：用户数、数据保留期、规则数、IOC 数、通知通道、API 调用量。
- 客户工单、通知中心、状态页。

### 安全合规

- MFA、SSO/SAML/OIDC。
- 数据导出、删除、保留策略。
- 客户级数据处理协议支撑。
- 管理后台操作强审计。

### 运维监控

- 多实例指标、队列削峰、SLO、错误预算。
- 租户级成本和资源用量。
- 灰度发布、回滚、事故告警和值班机制。

### 验收标准

- 可同时服务多个付费客户。
- 可按租户计量并限制用量。
- 可升级/降级套餐并立即影响权限和配额。
- 具备 SaaS 级状态页、告警和值班流程。

### 预计工程任务

- 新增 Plan、Subscription、Quota、UsageMeter、BillingAccount 模型。
- 增加用量采集与配额拦截。
- 接入支付或账单系统。
- 增加 SSO/MFA。
- 建立 SaaS 运维后台。

## 5. Phase D：规模化运营与合规

### 技术目标

- 建立区域化部署、灾备、数据生命周期治理。
- 模型质量运营：误报反馈、漂移监控、灰度、回滚。
- 合规证据自动化生成。
- 形成持续运营闭环。

### 产品能力

- 客户成功看板。
- 误报反馈和处置质量分析。
- 合规报表导出。
- SLA/SLO 报告。

### 安全合规

- 等保、ISO27001、SOC2 风格控制项映射。
- 审计留存、数据保留、数据删除、密钥轮换。
- 季度恢复演练和安全事件响应流程。

### 运维监控

- 容量规划、成本监控、稳定性评分。
- 重大客户独立监控策略。
- 自动化合规证据包。

### 验收标准

- 季度恢复演练通过。
- 合规证据可按客户和时间范围导出。
- 模型漂移、误报率、漏报风险可运营。
- SLA/SLO 达到商业合同要求。

### 预计工程任务

- 建立数据生命周期策略。
- 建立合规证据导出中心。
- 建立模型质量运营看板。
- 建立灾备演练流程和报告模板。
- 建立客户成功运营后台。

## 6. P0 阻塞项

- 数据库迁移治理缺失。
- 多租户 `tenant_id` 架构尚未建立。
- 身份体系仍偏单企业环境变量模式。
- 响应动作缺少商业化审批和误封保护。
- 缺 License、套餐、配额、计量、计费。
- 缺租户级数据保留、删除、导出和合规证据。

- 云安全组/EDR 全厂商适配。
- 模型自动重训平台。
- 移动端 App。
- 完整 SOAR 编排。
- 跨区域多活。
- 数据湖级报表。
