# AI-Security-Guardian 商业化风险清单

## 1. 总体风险判断

当前系统已有生产化基础，但商业化风险主要集中在数据库演进、租户隔离、自动响应、模型可信、SaaS 计量和合规证据六个方向。这些风险不处理，会直接影响客户交付、续费、采购审查和规模化运营。

## 2. P0 风险

| 风险 | 当前表现 | 商业影响 | 缓解措施 |
|---|---|---|---|
| 数据库迁移缺失 | 当前生产文档仍说明尚未引入 Alembic/Flask-Migrate，`create_all()` 仅适合首次空库 | 后续升级容易损坏生产库，无法稳定交付 | 立即引入迁移框架、迁移评审、回滚 SQL、发布 gate |
| 多租户隔离缺失 | 现有核心模型未见 `tenant_id` | 无法进入多企业/SaaS，后补成本高且易越权 | Phase B 前完成租户模型和强制过滤 |
| 身份体系不足 | 当前偏单管理员环境变量 + 基础 RBAC | 无法支撑企业成员管理、SSO、审计责任归属 | 增加用户、组织、成员、角色、API Key、MFA/SSO |
| 自动响应误伤 | 封禁/隔离一旦误触可能影响客户业务 | 造成重大生产事故和客户信任损失 | 默认 dry-run、审批、白名单、定时解封、误封演练 |
| 商业计量缺失 | 缺套餐、配额、License、UsageMeter | 无法形成可收费、可限额、可续费的 SaaS 闭环 | 建立 Plan、Subscription、Quota、UsageMeter |
| 合规证据不足 | 审计有基础，但缺客户级证据包和数据生命周期 | 大客户采购、等保/ISO/SOC2 审查受阻 | 提前固化审计事件、证据导出、数据保留和删除策略 |

## 3. 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 特征与模型不一致 | 检测结果可信度下降 | 继续强化 manifest、schema 校验、训练/推理字段一致性 |
| 模型漂移 | 误报/漏报上升 | 建立误报反馈、漂移监控、灰度发布、快速回滚 |
| Redis/DB 故障 | 告警延迟、队列堆积或数据写入失败 | 监控 Stream lag/pending、DB 连接池、重试和恢复回放 |
| 依赖外部通知通道 | SMTP/Webhook 异常影响处置闭环 | 通知失败重试、死信记录、可视化失败状态 |
| Guardian 高权限运行 | 抓包和防火墙能力带来主机安全风险 | 最小权限、隔离部署、审计、只在授权节点启用 |

## 4. 产品风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 安全能力难以解释 | 客户不理解告警依据，影响信任 | 增加告警解释、证据字段、命中规则、模型版本 |
| 误报处置流程不足 | 客户运营成本高 | 增加确认、忽略、误报反馈、白名单建议 |
| 报表不够采购友好 | 管理层难以看到价值 | 增加风险趋势、拦截价值、响应效率、合规摘要 |
| 私有化交付复杂 | 项目制交付成本高 | 标准化安装包、配置校验、交付模板、自动化巡检 |

## 5. 安全合规风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 租户越权 | SaaS 重大安全事故 | 强制租户上下文、越权测试、代码审查清单 |
| 敏感信息泄露 | 密钥、Webhook、SMTP 凭证泄露 | 密钥不入日志、配置加密、密钥轮换 |
| 审计不可追溯 | 事故复盘和合规审查失败 | 哈希链、只追加日志、审计事件入库、证据导出 |
| 数据删除不可证明 | 合规风险 | 数据生命周期、删除任务、删除证明、审计记录 |

## 6. 运维风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 缺少 SLO | 无法承诺商业 SLA | 定义可用性、延迟、队列堆积、检测延迟 SLO |
| 发布回滚不可控 | 升级事故扩大 | 灰度发布、版本 pin、数据库回滚、模型回滚 |
| 备份不可恢复 | 灾难恢复失败 | 定期恢复演练，记录 RTO/RPO |
| 成本不可控 | SaaS 毛利不稳定 | 租户级成本计量、配额、限流 |

## 7. 风险优先级建议

### 立即处理

- 数据库迁移治理。
- 租户隔离架构设计。
- 响应审批和误封恢复。
- 商业计量数据模型。

### 近期处理

- SSO/MFA。
- 用量看板。
- 租户级审计。
- 模型质量运营。

### 后续处理

- 跨区域多活。
- 自动化根因分析。
- 全厂商 EDR/云防火墙联动。
- 高级 SOAR 编排。
