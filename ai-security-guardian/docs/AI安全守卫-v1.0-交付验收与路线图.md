# AI安全守卫 v1.0 交付验收与路线图

> 版本：v1.0  
> 日期：2026-04-27  
> 定位：面向评审、交付和上线准入的验收文档  
> 范围：明确当前实现、生产 v1.0 验收标准、未完成能力路线图和风险清单。

---

## 1. 交付结论

当前 AI-Security-Guardian 代码不属于失败项目。它已经形成安全防护系统的主要模块骨架，适合作为 v0.8 原型和生产 v1.0 的工程基础。

当前版本尚不能直接作为生产防护系统上线，主要原因是实时流量链路、特征模型一致性、持久化、响应闭环和运维观测仍需补齐。生产 v1.0 应以“可运行、可审计、可回滚、可验收”为上线目标。

## 4. 生产 v1.0 验收标准

### 4.1 功能验收

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| F-01 | 网络流量检测 | 连续 TCP/UDP/ICMP 流可形成 flow 特征并进入检测器 |
| F-02 | Web 攻击检测 | SQLi、XSS、命令注入、路径遍历可触发告警，且包含来源 IP |
| F-03 | 威胁情报前置过滤 | 本地 IOC 命中可跳过模型推理并生成高置信告警 |
| F-04 | 融合决策 | 多引擎结果可融合，等级升级规则稳定 |
| F-05 | 告警持久化 | Web 重启后历史告警仍可查询 |
| F-06 | 状态流转 | 告警可确认、解决、忽略，并保留历史记录 |
| F-07 | 响应动作 | high/critical 可产生封禁或隔离动作记录 |
| F-08 | 解封回滚 | 封禁 IP 可手工解封，生产路线需支持定时解封 |
| F-09 | 报告生成 | 日/周/月报告基于持久化数据生成 |
| F-10 | 审计巡检 | 日志完整性校验可运行并输出 valid 状态 |

### 4.2 性能验收

| 指标 | 目标 |
|---|---|
| 端到端检测延迟 | P95 < 100ms |
| Web API 响应 | P95 < 300ms |
| Redis Stream 消费堆积 | 正常流量下无持续增长 |
| 模型推理失败率 | < 1% |
| 采集丢包率 | 在目标环境压测下可观测、可告警 |

### 4.3 模型验收

| 指标 | 目标 |
|---|---|
| Accuracy | > 95% |
| Precision | > 93% |
| Recall | > 95% |
| F1 | > 94% |
| FPR | < 3% |
| FNR | < 5% |
| 模型版本 | 每个线上模型必须有 manifest |
| schema 一致性 | 训练和推理特征列完全一致 |

### 4.4 安全验收

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| S-01 | API 认证 | 除健康检查和登录外，API 均需 JWT |
| S-02 | 默认密钥 | 生产环境无默认 `SECRET_KEY` |
| S-03 | 管理员密码 | 使用 `ADMIN_PASSWORD_HASH`，禁止默认明文密码 |
| S-04 | CORS | 仅允许白名单 Origin |
| S-05 | 命令注入 | IP 参数严格校验，subprocess 不使用 shell=True |
| S-06 | SSRF | Webhook URL 禁止 localhost 和元数据地址 |
| S-07 | 日志完整性 | 哈希链可校验 |
| S-08 | 敏感信息 | API Key、密码不进入日志 |
| S-09 | Redis 暴露 | Redis 仅内网访问并启用密码 |
| S-10 | 容器权限 | Web/API 非 root 运行，Guardian 高权限最小化（见 `docs/deployment.md`） |

## 5. 生产路线图

### R1：检测链路可信

目标：让实时流量和 Web 日志都能稳定进入检测链路。

交付：

- 批量/滑动窗口流聚合。
- Web 特征保留 `src_ip`。
- 网络流特征补齐 duration、rate、window 统计。
- 检测主循环异常隔离和延迟指标。

验收：

- 模拟 5 元组流跨多个 tick 输入后能输出 flow 特征。
- Web 攻击告警包含来源 IP 并可触发响应策略。

### R2：状态持久化

目标：Web 控制台从内存态迁移到数据库。

交付：

- Alert、AlertHistory、Rule、IOC、Setting、ResponseAction、AuditEvent 数据模型。
- Redis Stream consumer。
- REST API 查询数据库。
- Web 重启数据不丢失。

验收：

- Guardian 写入 Redis 后，Web 消费、入库、ack、推送。
- 告警状态流转可追溯。

### R3：模型治理

目标：让模型可追踪、可热更新、可回滚。

交付：

- 模型 manifest。
- schema 校验。
- ModelRegistry。
- 热更新和回滚。
- 推理指标记录。

验收：

- schema 不匹配模型不可上线。
- 新模型加载失败时旧模型继续服务。
- 每条模型告警记录 model_version。

### R4：响应闭环

目标：高危威胁可自动响应，且可回滚、可审计。

交付：

- SMTP/Webhook 通知。
- FirewallManager 抽象。
- 限速、端口封禁、定时解封。
- HostIsolationProvider。
- 响应审批和回滚记录。

验收：

- high 告警自动通知并产生封禁记录。
- critical 告警产生隔离动作或人工审批任务。
- 响应失败可见、可重试。

### R5：运维可观测

目标：满足生产运维和持续迭代。

交付：

- Prometheus 或兼容指标接口。
- 日志完整性巡检。
- 模型质量报表。
- CI/CD 流水线。
- 部署与回滚手册。

验收：

- 关键指标可采集。
- 巡检失败产生告警。
- 自动化测试覆盖 P0/P1 链路。

## 6. 风险清单

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 特征与模型不一致 | 检测结果不可信 | R1/R3 优先修复 schema 契约 |
| Web 内存态 | 重启丢数据 | R2 迁移数据库 |
| 自动封禁误伤 | 影响正常业务 | 阈值、白名单、审批、定时解封 |
| 高权限响应 | 系统安全风险 | 最小权限、审计、provider 抽象 |
| 情报误报 | 大量误封 | 多源合并、TTL、分数阈值、人工确认 |
| 模型漂移 | 误报/漏报上升 | 指标回收、定期重训、灰度发布 |
| Redis/DB 故障 | 告警丢失或延迟 | 缓冲降级、重试、恢复回放 |
| 日志被篡改 | 事后追溯失效 | 哈希链、巡检、只追加存储 |

## 7. 上线准入清单

上线前必须完成：

- 生产 `.env` 完成配置，且无默认密钥、默认密码（`FLASK_ENV=production` 时：`SECRET_KEY` 非示例且长度达标、`ADMIN_PASSWORD_HASH` 必填、`REDIS_PASSWORD` 必填、`ALLOWED_ORIGINS` 无 `*`）。
- 数据库迁移完成并备份策略可用。
- Redis 启用 `requirepass`，Compose 默认仅绑定 `127.0.0.1:6379`，不向公网 `0.0.0.0` 暴露；详见 `docs/deployment.md`。
- Web/API、Guardian、Redis、数据库健康检查通过（含 `/readyz` 对生产配置项的检查）。
- P0/P1 测试通过；**`python -m pytest -q` 全绿**。
- 模型 manifest 完整，schema 一致性校验通过。
- dry-run 与真实响应模式均演练通过。
- 审计日志完整性校验通过。
- Nginx TLS 和 WSS 转发验证通过。
- 回滚方案经过演练。
- **安全回归（v1.0 硬化）**：缺 `SECRET_KEY` 启动失败；无 JWT 访问受保护 API 返回 401；非白名单 Origin 无 CORS 放行；SSRF Webhook（localhost/元数据/内网解析）被拒绝；Webhook/SMTP 错误不回显密钥；防火墙 `subprocess` 无 `shell=True`、IP 严格校验。

## 8. 验收测试场景

| 场景 | 输入 | 期望结果 |
|---|---|---|
| 正常 Web 请求 | `/api/items?id=1` | 不产生攻击告警 |
| SQL 注入 | `/login?u=admin' OR 1=1--` | web_attack high 告警 |
| 双层编码 XSS | `%253Cscript%253Ealert(1)` | web_attack high 告警 |
| 命令注入 | `/ping?host=127.0.0.1;cat /etc/passwd` | web_attack high 告警 |
| IOC 命中 | 本地黑名单 IP 访问 | threat_intel high 告警 |
| 流量异常 | SYN 包突增 | ddos 或 anomaly 告警 |
| 模型缺失 | 删除某模型文件 | 该引擎降级，其余继续工作 |
| Redis 中断 | 停止 Redis | 本地降级并记录告警 |
| 审计篡改 | 修改 security.log | 完整性校验失败 |
| Web 重启 | 产生告警后重启 | 历史告警仍可查询 |

## 10. 最终判定

当前系统可以作为生产 v1.0 的基础，但不能跳过 R1-R3 直接上线。建议先完成“检测链路可信、状态持久化、模型治理”三项，再进入响应闭环和运维可观测建设。完成路线图后，AI-Security-Guardian 具备落地为生产防护系统的现实可行性。
